- Existing API endpoint: POST /api/v1/auth/register -- Accepts name, email, and password to initiate user registration. Validates all fields server-side, enforces email uniqueness, hashes the password, persists the user in PENDING state, and triggers asynchronous OTP dispatch via SMTP. Returns a confirmation that a verification email has been sent. (see [references/SVC-001.md](./references/SVC-001.md))
- Existing API endpoint: POST /api/v1/auth/verify-otp -- Accepts the user's email and the OTP code received via email. Validates the OTP against the stored record (existence, expiry within 5-minute window, single-use flag). On success, marks the OTP as used and transitions the user account from PENDING to ACTIVE state. (see [references/SVC-001.md](./references/SVC-001.md))
- Existing API endpoint: POST /api/v1/auth/login -- Accepts email and password. Validates all four conditions server-side: email exists, password matches bcrypt hash, account is ACTIVE (verified), account is not deleted. On success, issues a signed JWT token. All failure conditions return an identical generic error message to prevent user enumeration. Rate limiting is enforced after repeated failed attempts. (see [references/SVC-001.md](./references/SVC-001.md))
- Existing API endpoint: POST /api/v1/auth/logout -- Terminates the authenticated user's session. For the JWT-based stateless model, instructs the client to discard the token. Server-side session invalidation is performed where a session store is maintained. Subsequent requests using the invalidated token are denied. (see [references/SVC-001.md](./references/SVC-001.md))
- Existing API endpoint: GET /api/v1/dashboard -- Returns the authenticated user's profile data for display on the Dashboard. Access is gated by server-side JWT validation. The response includes user profile fields and signals whether the Delete Account option should be rendered (based on valid session). Missing, expired, tampered, or previously invalidated tokens result in 401. (see [references/SVC-001.md](./references/SVC-001.md))
- Existing API endpoint: DELETE /api/v1/users/me -- Permanently and irreversibly deletes the authenticated user's account. The target account is derived exclusively from the server-side JWT session — no client-supplied account identifiers are accepted. Validates the Bearer token, confirms session-to-account ownership, then executes hard-delete of all user data and immediately invalidates all active sessions for the deleted account. Transactional integrity ensures no partial deletion states. (see [references/SVC-001.md](./references/SVC-001.md))
- Existing API endpoint: GET /api/v1/health -- Returns the health status of the application and its dependency on the PostgreSQL database. Used by infrastructure monitoring tools (UptimeRobot, AWS CloudWatch). Does not require authentication. (see [references/SVC-001.md](./references/SVC-001.md))
